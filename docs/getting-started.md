# Getting started

Set up a development machine, run Aiko in each mode, and fix common problems. No Firebase account is needed for local work: the Firebase Emulator Suite provides Auth, Firestore, Storage, Functions and Hosting.

## Prerequisites

| Tool | Version | Used for |
| --- | --- | --- |
| Flutter (stable) | ≥ 3.44 (Dart ≥ 3.12); CI pins 3.47.7 in `.github/actions/setup-flutter/action.yml` | App |
| Node.js | 22 | Firebase CLI, Functions, emulator tests |
| Java | 21 | Firestore and Storage emulators |
| Android Studio / Xcode | current | Native builds only |

## First-time setup

```sh
flutter pub get
npm ci                                  # Firebase CLI and rules-test tooling
npm --prefix firebase/functions ci
npm run functions:build                 # compiles firebase/functions/src to lib/
dart run sqflite_common_ffi_web:setup   # writes web/sqflite_sw.js and web/sqlite3.wasm (gitignored)
cp .env.example .env                    # emulator defines; .env is gitignored
```

Localization files under `lib/l10n/app_localizations*.dart` are generated by `flutter pub get` and the Flutter build ([Localization](localization.md)).

## Run modes

### 1. Full local stack (recommended)

Build the web app against the emulators, then start them. Hosting serves `build/web`.

```sh
flutter build web --dart-define=FIREBASE_PROJECT_ID=demo-aiko \
  --dart-define=FIREBASE_EMULATOR_HOST=127.0.0.1
npm run firebase:start
```

| Service | Address |
| --- | --- |
| App (Hosting emulator) | http://localhost:8080 |
| Emulator UI | http://127.0.0.1:4000 |
| Auth / Firestore / Storage / Functions | 127.0.0.1:9099 / 8081 / 9199 / 5001 |

Create an email/password account in the app, or tap **Continue without an account** to try guest mode. Password-reset links appear in the Auth emulator output. Emulator data is exported to `.firebase-data/` on Ctrl-C and imported on the next start (gitignored; back it up if it matters). Keep using the same host and port, or the browser's local storage won't carry over.

For hot reload, keep the emulators running and run the app separately:

```sh
flutter run -d chrome --web-port=8082 --dart-define-from-file=.env
```

To try the web app offline, add the service-worker precache after the build, then start the emulators: `flutter build web …` (as above), `npm run web:precache`, `npm run firebase:start`. Open the app once online, then go offline (browser dev tools → Network → Offline) and reload. `flutter run -d chrome` has no working service worker (it removes itself), so it can't start offline ([Architecture → Web offline loading](architecture.md#web-offline-loading)).

### 2. Local-only mode

Omit every Firebase define:

```sh
flutter run -d chrome     # or any device
```

The app opens straight on the dashboard, stores data in the local record store, `aiko_local.sqlite` (IndexedDB on the web), seeds a Cash and a Bank Account, and has no sign-in, sync or cloud features ([Architecture → Runtime modes](architecture.md#runtime-modes)). Browser storage needs HTTPS or localhost and is lost when site data is cleared.

### 3. Mobile against the emulators

```sh
flutter run -d <device> --dart-define=FIREBASE_PROJECT_ID=demo-aiko \
  --dart-define=FIREBASE_EMULATOR_HOST=10.0.2.2   # Android emulator; iOS simulator uses 127.0.0.1
```

A physical phone needs your machine's LAN IP in `FIREBASE_EMULATOR_HOST`, and the emulator `host` values in `firebase.json` bound to that interface. Sign in with the same account as the web app to share data. Google sign-in needs a real project; use email/password locally.

### 4. Against a real Firebase project

Put the production values in `.env` (remove `FIREBASE_EMULATOR_HOST`):

```sh
FIREBASE_PROJECT_ID=aiko-prod
FIREBASE_API_KEY=…
FIREBASE_APP_ID=…
FIREBASE_MESSAGING_SENDER_ID=…
FIREBASE_STORAGE_BUCKET=…
FIREBASE_AUTH_DOMAIN=…
```

Then run `flutter run --dart-define-from-file=.env`. Android and iOS need their own Firebase app IDs, and native Google sign-in needs `GOOGLE_WEB_CLIENT_ID` (Android) and `GOOGLE_IOS_CLIENT_ID` (iOS, plus the reversed client-ID URL scheme in `Info.plist`). Web deploys are automated ([Deployment](deployment.md)).

## Configuration reference

All app configuration is compile-time `--dart-define`. Every value is public client configuration; secrets belong in Functions only ([Security](security.md)).

| Define | Default | Purpose |
| --- | --- | --- |
| `FIREBASE_PROJECT_ID` | empty (local-only) | Firebase project; any value enables Firebase |
| `FIREBASE_EMULATOR_HOST` | empty | Use emulators at this host; requires a `demo-` project ID |
| `FIREBASE_API_KEY`, `FIREBASE_APP_ID`, `FIREBASE_MESSAGING_SENDER_ID` | demo placeholders | Firebase app options |
| `FIREBASE_STORAGE_BUCKET` | `<project>.appspot.com` | Storage bucket (new projects use `<project>.firebasestorage.app`, so set it) |
| `FIREBASE_AUTH_DOMAIN` | `<project>.firebaseapp.com` | Auth domain for pop-up sign-in |
| `FIREBASE_REGION` | `us-central1` | Region the app calls Functions in; Functions deploy to `us-central1`, so keep the default ([Backend](backend.md#functions)) |
| `GOOGLE_WEB_CLIENT_ID` | empty | Android Google sign-in (`serverClientId`) |
| `GOOGLE_IOS_CLIENT_ID` | empty | iOS Google sign-in |

Functions provider secrets live in `firebase/functions/.secret.local` locally, created from `.secret.local.example` with `local-unconfigured` placeholders. Set real values there to try Ask Aiko, LINE, OCR or price feeds against the emulators ([Backend](backend.md#secrets-and-configuration)).

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `Local emulators must use a demo- Firebase project ID.` | Emulator builds need `FIREBASE_PROJECT_ID=demo-…` |
| Web build or runtime can't find `sqflite_sw.js` / `sqlite3.wasm` | Run `dart run sqflite_common_ffi_web:setup` |
| Hosting emulator shows an old app | Rebuild `build/web`; Hosting serves the last build |
| Emulators fail to start: Java not found / port in use | Install Java 21; stop whatever holds ports 4000, 5001, 8080, 8081, 9099, 9199 |
| Java crashes under Android/proot (Termux, Alpine) | `AIKO_ANDROID_PROOT_JAVA=1 npm run firebase:start` builds a process-scoped shim (`tool/proot_java_exec_memory.c`; needs `gcc musl-dev`). Low memory: `JAVA_TOOL_OPTIONS='-Xmx512m -XX:+UseSerialGC'` |
| SQLite FFI tests fail on Alpine | Temporarily set `hooks.user_defines.sqlite3.source: system` in `pubspec.yaml` with `sqlite-dev` installed; don't commit it |
| Ask Aiko says the provider isn't configured (503) | Set `AI_API_KEY`, `AI_MODEL`, `AI_BASE_URL` in `firebase/functions/.secret.local` and restart the emulators |
| "A change could not sync" snackbar | A write was rejected (Security Rules or expired sign-in), or a file failed to upload 5 times; check the emulator logs |
| The web app won't open offline | Run `npm run web:precache` after `flutter build web`, and load the app once online first; `flutter run` builds have no service worker |
| `web:precache` fails listing Firebase SDK files | Run it in the checkout that ran `flutter build web` (it reads `.flutter-plugins-dependencies`) |
| "Syncing…" stays while online | The device has a network but can't reach Firebase (captive portal, emulators stopped); changes stay queued until it can |
| Google sign-in fails locally | Expected with emulators; use email/password |
