# Localization

Aiko is fully available in **English (`en`)** and **Thai (`th`)**. Every user-facing string, including the built-in category names, notifications, exported files and Ask Aiko's replies, comes in both languages. Tests fail when a string is hard-coded, missing a translation, or unused.

## Files

| File | Role |
| --- | --- |
| `l10n.yaml` | `gen-l10n` config: ARB directory `lib/l10n`, template `app_en.arb`, output `app_localizations.dart`, non-nullable getters |
| `lib/l10n/app_en.arb` | English strings (template), about 1,500 keys, grouped by key prefix (`tx…`, `accounts…`, `calc…`) |
| `lib/l10n/app_th.arb` | Thai translations, same keys |
| `lib/l10n/app_localizations*.dart` | Generated by `flutter pub get` or any build; gitignored. Don't edit |
| `lib/l10n/l10n.dart` | `context.l10n` accessor; `currentL10n()` for code without a `BuildContext` |
| `lib/l10n/domain_labels.dart` | `label(l10n)` for every enum shown to users (account, transaction, category and rule types, frequencies, gender, theme), `currencyDisplayName`, `investmentAssetClassLabel` |
| `lib/features/categories/presentation/category_names.dart` | `displayName(l10n)` for built-in categories and groups |
| `lib/app/locale_controller.dart` | `AppLocaleController`: which language to render |
| `assets/fonts/noto_sans_thai/` | Bundled Noto Sans Thai (SIL OFL 1.1, `OFL.txt`) |

## Choosing the language

`AppLocaleController` resolves the language on startup:

1. A saved choice (`aiko_language_code`, `en` or `th`) wins. It's a synced preference, so it follows the user across devices when signed in; a choice made before signing in moves into the account if the account has none.
2. Otherwise the device language, if supported ("System default"). This is also used when the saved choice can't be read, offline included.
3. Otherwise English.

Settings → Language offers System default, English and Thai; each language is listed in the current language and in itself ("Thai (ไทย)", "อังกฤษ (English)"). On Android 13+ the per-app language setting lists the same two (`android/app/src/main/res/xml/locales_config.xml`); iOS declares them in `CFBundleLocalizations` (`ios/Runner/Info.plist`).

`AikoApp` sets `Intl.defaultLocale` to the selected language, so `DateFormat` and `NumberFormat` without an explicit locale follow it: Thai month and day names (`ต.ค.`, `อา`) and Thai number formatting. Years stay Gregorian.

## Writing strings in code

| Where | How |
| --- | --- |
| Widgets | `context.l10n.key` (import `lib/l10n/l10n.dart`), or `final l10n = context.l10n;` at the top of `build` |
| Before an `await` in a handler | Read `final l10n = context.l10n;` first, then use `l10n` after the gap (the `use_build_context_synchronously` lint enforces this) |
| `initState` | `currentL10n()`; context lookups aren't allowed there |
| Providers that build text | Watch the language: `lookupAppLocalizations(ref.watch(appLocaleControllerProvider)…)` (see `_l10nOf` in `lib/app/providers.dart`), so the text updates when it changes |
| Pure services | Take `AppLocalizations l10n` as a parameter (for example `buildNotifications`, `CategoryBudgetProgressService.recommendation`); tests pass `lookupAppLocalizations(const Locale('en'))` |
| Background work and seeded data | `currentL10n()` (reminder notification channel, default account names at sign-up, auto-captured transaction notes) |
| `const` tables (navigation items, intro slides) | Store a tear-off `String Function(AppLocalizations)` instead of a string; see `aikoNavigationItems` |
| Enum values | `value.label(l10n)` from `domain_labels.dart`; never `value.name` |

Errors from repositories and services stay English for logs. Screens map them to localized text by type or code: `authErrorMessage` maps Firebase Auth codes and takes an `offline` message for network failures; `LineLinkError` (`emptyCode`, `invalidCode`, `expiredCode`, `alreadyLinked`, `tooManyAttempts`, `signedOut`, `offline`, `failed`, mapped from the function's error codes by `lineLinkErrorForCode`), `ChatFailure` and `ReceiptOcrFailure` are enums; `localizedAccountValidationMessage` maps `AccountValidationMessages`. Don't show `$error` to users.

### Built-in categories

Built-in categories and groups are stored with their English template name. `category.displayName(l10n)` shows the translated name while the stored name still equals the template's, and exactly what the user typed once they rename it. Editors start from the display name and save it through `storedCategoryName`, so saving without renaming keeps the row translatable. Use `displayName` wherever a category or group name is shown, searched or exported.

### Data entered in the user's language

- **Voice entry** (`VoiceTransactionParser`) understands Thai phrases: amounts with thousands separators and `บาท`, `เมื่อวาน`/`พรุ่งนี้`, merchants after `ที่(ร้าน)`/`จาก`, and income words (`ได้รับ`, `เงินเดือน`, `รายได้`). The merchant keeps the casing typed and ends at a date word or connective in either language (`yesterday`, `today`, `for`, `with`, `เมื่อวาน`, `วันนี้`, …); in English a name after "at"/"from" wins over one after "on"/"for" ("for lunch at KFC" → KFC).
- **Receipt OCR** (`ReceiptOcrService.extractDate`) finds Thai totals (`ยอดรวม`, `รวมทั้งสิ้น`, `ยอดสุทธิ`, `ยอดชำระ`) and reads dates the way Thai receipts print them:
  - Day first: 05/10/2026 is 5 October. Month first only when the second number can't be a month (05/21/2026) or the receipt labels its dates MM/DD, and never for Buddhist-era years.
  - Four-digit years above 2400 are Buddhist era (21/05/2569 → 21 May 2026). A two-digit year more than one ahead of the current one is Buddhist too (69 in 2026 → 2569 → 2026); otherwise it is 20xx.
  - Dates after tomorrow or more than five years back are skipped; with no usable date the form keeps today.
- **Auto-capture** parses English and Thai bank messages (`BankMessageParser`): it recognizes Thai OTP warnings, and blanks Thai dates (`13 ต.ค. 69`) and account or reference labels (`บช`, `เลขที่อ้างอิง`) so their numbers aren't read as the amount ([Features](features.md#auto-capture-android)).

### Ask Aiko

The app sends its language with every chat request (`systemContext.locale`); the Cloud Function tells the model to reply in Thai or English and to end with the disclaimer in that language (`languageInstruction` in `firebase/functions/src/chat.ts`). LINE has no app language, so Aiko replies in the language of the user's message, and the pairing and fallback messages are Thai for Thai messages, English otherwise, and both for a new follower (`lineCopy` in `firebase/functions/src/index.ts`). Prompt suggestions, the greeting and chat errors are ARB strings.

### Exports

CSV column headers, transaction types and category names, and the HTML statement (title, totals, table, footer, `<html lang>`) use the selected language. The format choice "CSV" stays as-is; "CSV (opens in Excel)" and "HTML statement (print to PDF)" are ARB strings.

## Fonts

Hanken Grotesk and Manrope (bundled assets used through `google_fonts`, which never downloads them; [Design system → Typography](design-system.md#typography)) have no Thai glyphs. `AikoTypography` sets `NotoSansThai` as the fallback family, bundled in `pubspec.yaml` (`fonts:`, weights 400–800, about 240 KB). Text in both languages therefore renders offline and on the first web load, without waiting for a font download.

## Adding or changing a string

1. Add the key to `app_en.arb` and the Thai to `app_th.arb`. Name it with the screen's prefix (`txAddTitle`, `accountsDeleteQuestion`). Placeholders use ICU syntax with `placeholders` metadata in the English file; use `Object` for pre-formatted values and `int` with `{count, plural, …}` for counts (Thai needs only `other`).
2. Run `flutter pub get` (or any build) to regenerate.
3. Use it as `context.l10n.yourKey` (or a local `l10n`).
4. Run `flutter test test/l10n`.

Aiko's Thai voice is warm and polite; when Aiko speaks as herself, she ends sentences with ค่ะ/นะคะ where natural. Use the app's terms consistently: รายการ (transaction), บัญชี (account), หมวดหมู่ (category), งบประมาณ (budget), รายรับ/รายจ่าย (income/expense), โอนเงิน (transfer).

## Tests

| Test | Fails when |
| --- | --- |
| `test/l10n/hardcoded_strings_guard_test.dart` | A string literal with letters is passed to `Text(` or a text parameter (`label:`, `title:`, `tooltip:`, `hintText:`, `message:`…) in `lib/`. Brand names and format names carry `// l10n-ignore` |
| `test/l10n/arb_completeness_test.dart` | Thai is missing a key or placeholder; a Thai value has no Thai script (except `aikoTab`, `glossaryAprTerm`, `txReminderBody`); a key isn't read through `l10n.`/`currentL10n().`; Android or iOS doesn't list a supported language |
| `test/l10n/domain_labels_test.dart` | An enum value lacks a distinct English or Thai label |
| `test/features/categories/category_names_test.dart` | A built-in category or group lacks a Thai name, or renamed rows get translated |
| `test/theme/thai_font_test.dart` | The bundled Thai font or its license goes missing |
| `firebase/functions/test/chat_prompt.test.cjs` | The chat prompt stops following the app language |

## Adding a language

1. Create `lib/l10n/app_<code>.arb` with every key, and add the code to `AppLocaleController.localeFor` and `_languageOptions` in `lib/features/settings/presentation/settings_screen.dart`.
2. Add it to `locales_config.xml`, `CFBundleLocalizations` and an `ios/Runner/<code>.lproj/InfoPlist.strings` for permission prompts.
3. Bundle a fallback font if the script isn't covered, extend `languageInstruction` and `lineCopy` in the Functions, and update `expect(languages, …)` in the completeness test.
